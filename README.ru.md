> **Пользуетесь ещё и zcode?** Взгляните на [zcode-switchman](https://github.com/mrzturn/zcode-switchman) — родственный open-source проект того же автора, который приносит такую же оркестрацию пользователям zcode.

> Контекст — на счётчике. Задачи диспетчируются сами.

![opencode-switchman — уровень воды в контексте ведёт стрелочника и задаёт маршрут](docs/assets/hero.svg)

> Интерактивная демо-презентация: [opencode-switchman в действии](https://mrzturn.github.io/opencode-switchman/)

Плагин оркестрации для [OpenCode](https://opencode.ai). Он делает две вещи — и делает их хорошо:

**1. Контроль уровня воды в контексте.** Контекст вашей сессии замеряется на каждом ходу. Чтение ограничено бюджетом на каждый ход, поэтому модель не сможет незаметно заглотить весь репозиторий; пороги soft / hard / force запускают сначала совет, затем сворачивание работы, а затем автоматическую передачу с резервной копией и сжатием; каждый отправленный субагент несёт собственный жёсткий лимит. Контекст перестаёт расти снежным комом — сессия может работать хоть весь день, и её собственная история не пожирает токены.

**2. Автоматическая диспетчеризация решений.** Ваша основная модель становится диспетчером: она профилирует каждую задачу и делегирует её субагентским оболочкам по шести когнитивным направлениям (economy / mechanical / main / hard / vision / review). Плагин обеспечивает детерминированные шлюзы, взвешенную оценку моделей и самовосстанавливающуюся изоляцию сбоев, а каждое решение о маршрутизации записывает в журнал.

Помимо этого:

- **Несколько моделей или подписок? Этот плагин создан именно для вас.** GitHub Copilot, GLM Coding Plan, DeepSeek — или любой другой провайдер opencode — оркестрируются как единый пул: порядок с учётом квот, обход пиковых окон, принудительное ревью между семействами моделей.
- **Только одна модель? Всё равно того стоит.** Контроль контекста и умная диспетчеризация сами по себе позволяют единственной модели оставаться рабочей сколь угодно долго — как бы долго ни длилась сессия, контекст никогда не раздувается.

## Установка

Одна команда — подходит и для первой установки, и для последующих обновлений. После выполнения перезапустите opencode.

```bash
curl -fsSL https://raw.githubusercontent.com/mrzturn/opencode-switchman/main/scripts/setup.sh | bash
```

или

```bash
npx -y opencode-switchman@latest
```

или

```bash
bunx opencode-switchman@latest
```

Любой из путей переписывает запись `plugin` в вашей конфигурации opencode на точную последнюю версию и вычищает устаревшие кэши. Ручная установка через npm, сборка из исходников и заметка «почему точные версии»: [Подробности установки](./docs/reference.md#installation).

Предпочитаете ничего не делать руками? Доверьте установку своему ИИ — вставьте этот промпт в используемый вами ИИ:

Заверши функциональную настройку: все параметры плагина находятся в отдельном файле `opencode-switchman.jsonc` в каталоге конфигурации opencode; при первом запуске он создаётся автоматически со значениями по умолчанию и инлайн-комментариями — сверь его с моими провайдерами (например, `zhipuai-coding-plan` / `deepseek` / `github-copilot`) и при необходимости поправь.

**Требования**: [opencode](https://opencode.ai), рекомендуется CLI/TUI (именно там диалоги, сайдбар и баннеры наиболее информативны; десктопное приложение использует ту же конфигурацию и то же состояние). Подойдёт любой провайдер; Copilot / GLM / DeepSeek дополнительно получают маршрутизацию с учётом квот. Учётные данные читаются только в режиме read-only из собственного auth opencode — плагин никогда не хранит секреты.

## Быстрый старт

Шесть шагов. Полное пошаговое руководство со скриншотами: **[docs/quick-start.md](./docs/quick-start.md)** / [中文](./docs/quick-start.zh.md).

1. **Подключите провайдеров** — `/connect` в TUI: Copilot OAuth, API-ключ DeepSeek; GLM Coding Plan прописывается в `opencode.json` как кастомный провайдер `zhipuai-coding-plan`.
2. **Выберите модели, которые войдут в оркестрацию** — `/models`, затем `ctrl+f`, чтобы добавить в избранные (в десктопном приложении — переключатели "Manage models").
3. **`/switchman-setup`** *(требуется один раз)* — мастер настройки проходит всю матрицу за один заход: в мультиселекте отметьте хотя бы одну модель для каждого из шести пулов задач (economy / mechanical / main / hard / vision / review), затем расставьте выбранные модели от самой сильной к слабой. Нет TUI? `/switchman-setup-chat` запускает тот же мастер в чате. Пока настройка не завершена, диспетчеризация задач жёстко заблокирована — для ненастроенных пулов больше нет значения по умолчанию «все модели». Сохранённый конфиг подхватывается на лету; перезапуск нужен только для регистрации совершенно новых провайдеров.
4. **Тонкая настройка** *(опционально)* — **`/modelRank`** вручную корректирует рейтинг способностей моделей, а **`/poolConfig`** редактирует списки кандидатов по каждому пулу в диалогах TUI (в чате — варианты `-chat`); ручные записи везде переопределяют исходные значения по умолчанию.
5. **Команды контекста**
   - **`/handover`** — сделайте резервную копию сессии и сожмите её вручную. Используйте, когда строка `[WATERMARK:SESSION]` становится большой или задача достигла удобной точки остановки, вместо того чтобы ждать автоматическую передачу.
   - **`/ctx-pause`** — отключите для этой сессии лимиты на чтение и авто-передачу. Используйте, когда нужно разом прочитать много крупных файлов и не жаль потратить токены; замер продолжается.
   - **`/ctx-resume`** — включите лимиты обратно. Сделайте это, как только массовое чтение закончилось; перезапуск opencode даёт тот же эффект.
6. **Перезапустите и проверьте** — посмотрите баннер `[ROUTES]`/`[LIMITS]` и панель `switchman` в сайдбаре; если что-то выглядит подозрительно, запустите `/switchman-doctor`. Дальше просто пользуйтесь opencode как обычно.

## Что вы получаете

**Основное**

- **Контроль уровня воды в контексте** — замер сессии в реальном времени (`[WATERMARK:SESSION]`), пороги soft/hard/force, бюджет чтения на ход, автоматически ограничивающий излишне жадное чтение, жёсткий лимит с резюмированием и завершением для каждого субагента и автоматическая передача (полная резервная копия + сжатие) на принудительном уровне.
- **Автоматическая диспетчеризация решений** — встроенный протокол диспетчера превращает вашу основную модель в диспетчера; шесть когнитивных направлений маршрутизируют работу нужной модели с нужным уровнем усилий; шесть детерминированных шлюзов проверяют каждую отправку; сбои взводят предохранители и изоляцию, и система восстанавливается сама.

**Дополнительно**

- **Оркестрация нескольких подписок** — маршрутизация с учётом квот между Copilot / GLM / DeepSeek (участвует любой провайдер), уступание пиковых окон, оценка с учётом биллинга, принудительное ревью между семействами моделей.
- **Ручное управление** — `/switchman-setup`, `/poolConfig`, `/modelRank`, `/expert`, `/handover`, `/ctx-pause`, `/ctx-resume`, `/switchman-doctor`, `/switchman-update`.
- **Наглядность** — живой баннер из четырёх строк в каждом системном промпте, панель в сайдбаре TUI, зеркалирование в панели tmux, рабочее пространство артефактов для каждой сессии и журнал аудита каждого решения о маршрутизации.

## Дорожная карта

В ближайших планах: поддержка квот для большего числа провайдеров — больше подписочных планов и пулов с оплатой по факту сверх Copilot / GLM / DeepSeek. Если ваш провайдер пока не охвачен, [создайте issue](https://github.com/mrzturn/opencode-switchman/issues): что строить дальше, решает реальное использование.
